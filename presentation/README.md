# حزمة العرض التقديمي — بديل عطر ٢

<div dir="rtl">

حزمة عرض مدتها **60 دقيقة** للمؤلف إلى **فريق فرونت-إند خبير** (عن الشفافية والبناء: من Oracle أحادي الملف إلى Next.js 16 ساكن كامل).

| الملف | المسؤولية |
|---|---|
| `slides.html` | الشرائح — ملف واحد مكتفٍ ذاتياً (شغّله بالمتصفح، بلا بناء، بلا اعتماديات) |
| `demo-script.md` | العرض الحيّ الـ 11 دقيقة — خطوات مرقّمة + احتياط + عبارات تُقال/تُتجنّب |
| `qa-guide.md` | 37 سؤالاً متوقعاً مع إجابة 30–60 ثانية، مرجع سطر من المصدر، ومقايضة |
| هذا الملف | أمر التشغيل، قائمة إعادة التحضير، ومصفوفة التوقيت |

## التشغيل

افتح `slides.html` بالمتصفح مباشرة (double-click) أو:

```bash
npx serve .

# أو أي خادم ثابت في جذر presentation/
```

- **اللغة:** عرض عربي RTL.
- **الشرائح:** 38 شريحة — افتح الفهرس بالاختصار `I`.

## اختصارات لوحة المفاتيح

| المفتاح | الإجراء |
|---|---|
| `←` / `↓` / `PageDown` / `Space` / `Enter` | التالي |
| `→` / `↑` / `PageUp` / `Backspace` | السابق |
| `Home` / `End` | أول / آخر شريحة |
| `F` | ملء الشاشة |
| `N` | نافذة ملاحظات المتكلم (نسخة منفصلة) |
| `I` | فهرس الشرائح (قائمة تخبر بالأرقام) |
| `Esc` | خروج (فهرس/ملء/ملاحظات) |
| لمس: سحب أفقي/انعكاس | التالي/السابق على الجوال |

التصميم RTL: «الأمام» = اليسار اتجاهياً. الجداول والأكواد تبقى LTR موضعياً.

## مكوّنات الشرائح

- عدّاد الشرائح أسفل يسار + شريط تقدم أعلى.
- مقتطفات أكواد عليها اسم الملف المصدر (مكتوب سطر المرجع).
- شريحة «النمط الخاطئ» (لا يوجد في الكود) موسومة **بادئة «⚠»** بوضوح لأغراض تعليمية.
- طبع PDF عبر `Ctrl+P` يدخل إلى وضع الطباعة (شرائح بلا صداع).

## ترتيب الاستخدام للتحضير

1. **شغّل العرض بنفسك** بالترتيب الطبيعي (الشرائح 1-38) — تحقق من التوقيت.
2. **راجع `qa-guide.md`** بتأنٍّ: اسأل نفسك كل سؤال وفكّر في الإجابة 30-60 ثانية وبنطق.
3. **درّب `demo-script.md`** 3 مرات أمام جهازك (بلا انقطاع زمني):
   - مرة بالقسيمة الكاملة 11 دقيقة ثم مرة بالقسيمة المضغوطة 5 دقائق (تبدأ من «الخطوة 2»).
4. **حدث هذا الملف** (README) قبل كل عرض لاحق: تحقق من الأرقام المرجعية في `qa-guide.md` و `demo-script.md`، ومن أرقام سطر المصدر، بأن المشروع لم يتغيّر منذ إعداد الحزمة.

## قائمة إعادة التحضير (قبل كل عرض)

- [ ] `git status` — إن كان العرض داخل repo، تحقق ألا ملفات نصف مكتملة تعترض (العرض من الملفات نفسها لا يلزم نظافة).
- [ ] `pnpm typecheck && pnpm lint && pnpm build` → سجّل النتيجة مع التاريخ (تُستعمل في الشرائح 2 والتقرير الختامي).
- [ ] `npx serve out -l 3001` ثم فحص `/` و `/quiz/` و `/404` واحداً واحداً من صفحة فارغة.
- [ ] اختبر الاختصارات في slides.html: F, N, I, Esc, Home/End، والاتجاه RTL للأسهم.
- [ ] اطبع نسخة PDF للشرائح وتأكد من التباين في جهاز العرض (خلفية داكنة + نص ذهبي).
- [ ] اطبع نسخة ورقية من `demo-script.md` (احتياط يدوي للعرض الحيّ).
- [ ] خطة احتياطية جاهزة: إن انقطعت الشبكة → الخطوط المحلية في `public/fonts/` تعمل بدل fallback، وإن تعطّلت الفلترة → اتبع «خطة الفشل» في demo-script.
- [ ] جهّز جملة احتياطية لفظية: ماذا تقول لو «تعذّر عرض الحيّ»؟ (متّفق عليها في demo-script).

## التكافؤ والمصداقية

- كل ثغرة مقصودة معلن عنها في slides/qa-guide (بلا ادعاء «بلا أخطاء» ولا «أعلى أمان» وراء الحقيقة).
- إن تغيّر المشروع (سجلات، خطوط، مفاتيح) بعد إعداد الحزمة — أعد جولة المراجع في qa-guide وحدّث الشرائح بالأرقام الجديدة.
- أرقام الأسطر في الحزمة صحيحة وقت التحضير؛ إذا عُدّل كود بعدها، راجع جولة مراجع الأسئلة قبل العرض.
